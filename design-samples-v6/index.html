COGI

AI 코드 리뷰 SaaS Spring Boot · React

GitHub PR을 가져와 AI가 코드를 리뷰하고, 이슈·약점 패턴·성장 추이를 팀 단위로 관리하는 서비스입니다. 저는 서비스에 들어오는 세 개의 관문 — 비로그인 체험, 구독 결제, 관리자 — 을 맡았습니다.

담당 비로그인(Guest) · 결제(Payment) · 관리자(Admin) 도메인 백엔드

A
비로그인 체험

가입 전에 먼저 써보게 한다. 단, 계정 없이도 남용은 막아야 한다.

  • 익명 식별 — guest_token 쿠키(24시간)로 비회원을 구분하고, 없으면 UUID를 새로 발급해 심습니다.
  • 체험 3회 제한 — Redis 카운터 guest:count:{token}를 increment로 올리고, 첫 요청에만 TTL 24h를 걸어 슬라이딩이 아니라 첫 사용 시점 기준으로 리셋되게 했습니다. 초과 시 403.
  • 등급 고정 — 게스트는 항상 FREE 프롬프트 + 경량 모델(GEMINI Flash)로 고정해 비용을 통제합니다.
  • 부차 로직 격리 — AI 사용량 로그는 userId=null로 남기되, 로그 저장이 실패해도 리뷰 응답은 계속되도록 감쌌습니다.
GUEST REVIEW FLOW 게스트 요청→ guest_token 쿠키(24h)→ Redis 카운터 3회/24h→ AI 리뷰(Flash·FREE)→ 사용량 로그(userId=null)
B
구독 결제

Toss 빌링키로 매달 자동 청구하되, 결제 한 건의 실패가 전체를 무너뜨리지 않게.

  • 빌링키 구독 — Toss로 빌링키를 발급받아 최초 구독 시 즉시 1회 청구하고, 실패하면 @Transactional로 구독 생성까지 롤백합니다.
  • 경계 검증 — 중복 ACTIVE 구독 차단, 결제수단 소유자 검증(남의 결제수단으로 구독 불가), 필수 약관 동의 확인.
  • 정기결제 배치 — BillingScheduler가 매일 자정 만료 구독을 조회하고, BillingProcessor가 건별 트랜잭션으로 청구합니다. 한 건이 실패해도 배치 전체가 멈추지 않도록 예외를 격리했습니다.
  • 실패 처리 — 청구 실패 시 해당 구독만 별도 트랜잭션으로 FREE 등급 강등. 플랜 변경은 일할계산해 히스토리로 남깁니다.
DAILY BILLING BATCH 매일 자정 cron→ 만료 구독 조회→ 건별 @Transactional 청구→ 실패 시 FREE 강등(격리)
C
관리자

운영자가 회원·공지·약관·사용량을 다루는 뒷단. 권한은 입구에서 막는다.

  • 권한 차단 — /api/admin/**는 JWT 필터가 심은 ROLE_ADMIN으로만 접근하게 하고, 비관리자는 403으로 끊습니다.
  • 회원 관리 — 회원 역할·상태 변경, 목록 조회.
  • 공지 발송 — 전체 공지 메일을 @Async 백그라운드로 보내고, 건별 실패를 로깅하며 발송 결과를 공지에 기록합니다.
  • AI 사용량 통계 — 기간별 사용 로그를 집계하고, userId→닉네임을 한 번의 IN 조회로 채워 N+1을 피했습니다.

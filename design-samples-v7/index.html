A · GUEST

비로그인 체험

가입 전에 먼저 써보게 한다. 단, 계정 없이도 남용은 막아야 한다.

  • 익명 식별 — guest_token 쿠키(24시간)로 비회원을 구분하고, 없으면 UUID를 새로 발급합니다.
  • 체험 3회 제한 — Redis 카운터를 올리며 첫 요청에만 TTL 24시간을 걸어, 슬라이딩이 아니라 첫 사용 시점 기준으로 리셋되게 했습니다. 초과 시 403.
  • 비용 통제 — 게스트는 항상 경량 모델과 FREE 프롬프트로 고정.
  • 부차 로직 격리 — AI 사용량 로그는 userId=null로 남기되, 저장이 실패해도 리뷰 응답은 계속되게 감쌌습니다.
GUEST REVIEW 요청› guest_token 24h› Redis 3회/24h› AI 리뷰› 사용량 로그(null)
B · PAYMENT

구독 결제

Toss 빌링키로 매달 자동 청구하되, 한 건의 실패가 전체를 무너뜨리지 않게.

  • 빌링키 구독 — 최초 구독 시 즉시 1회 청구, 실패하면 @Transactional로 구독 생성까지 롤백.
  • 경계 검증 — 중복 구독 차단, 결제수단 소유자 검증, 필수 약관 동의 확인.
  • 정기 배치 — 매일 자정 만료 구독을 건별 트랜잭션으로 청구. 한 건이 실패해도 배치가 멈추지 않게 격리하고, 실패 건만 FREE로 강등.
DAILY BILLING 자정 배치› 만료 구독› 건별 청구› 실패 시 FREE
C · ADMIN

관리자

운영자가 회원과 공지, 약관, 사용량을 다루는 뒷단. 권한은 입구에서 막는다.

  • 권한 차단 — /api/admin/**은 JWT가 심은 ROLE_ADMIN으로만 접근, 나머지는 403.
  • 회원 관리 — 역할과 상태 변경, 목록 조회.
  • 공지 발송 — 전체 메일을 @Async로 백그라운드 발송, 건별 실패를 로깅.
  • 사용량 통계 — 기간별 집계에서 닉네임을 IN 한 번으로 채워 N+1 방지.

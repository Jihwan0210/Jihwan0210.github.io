사용자 · 관리자 권한 분리

상황

관리자와 일반 사용자는 접근하는 라우트만 다를 뿐 실제 권한을 검증하는 로직이 없었습니다. 주소만 알면 일반 사용자도 관리자 화면에 들어갈 수 있었습니다. 화면을 나눈 것과 권한을 보호하는 것은 전혀 다른 문제였고, 근본 원인은 접근 제어 계층이 없다는 것이었습니다.

해결

라우트마다 검증 코드를 흩어놓는 대신 Laravel Middleware를 골랐습니다. 요청이 컨트롤러에 닿기 전에 인증 여부와 역할(Role)을 한곳에서 검증하고, 관리자 전용 라우트 그룹 전체에 일괄 적용했습니다.

결과

화면 분리와 권한 검증이 항상 함께 동작하는 구조가 됐습니다. 이 경험 이후 Java와 Spring Security에서도 인증·인가를 공통 계층으로 두는 방식을 이어갔습니다.

구현 상세

요청› Middleware 인증 · 역할 검증› 관리자 라우트 그룹› 컨트롤러
  • 컨트롤러마다 검증을 넣으면 새 화면을 추가할 때 빠뜨리기 쉬워, 요청 앞단에서 한 번에 거르는 Middleware를 택했습니다.
  • 인증 여부와 역할(Role)을 함께 확인해, 로그인만 했을 뿐인 사용자가 관리자 라우트로 새지 않게 했습니다.

예약 · 후기 · 공지

이용자가 숙소를 고르고 예약한 뒤 후기를 남기기까지, 운영자가 공지로 안내하기까지의 흐름을 혼자 설계했습니다.

숙소 등록› 예약› 후기 · 평점› 공지› 관리자 CRUD
  • 숙소 정보 등록, 예약, 후기, 공지사항, 관리자 CRUD와 메시지 기능을 구현했습니다.
  • 숙소 · 예약 · 후기가 서로 물린 구조라, 쿼리를 직접 쓰기보다 Eloquent ORM의 관계 정의로 다뤘습니다.

인증 · 세션

상황

로그인 상태를 Context 메모리에만 들고 있어서, 새로고침하거나 주소로 직접 들어오면 로그아웃 상태로 돌아갔습니다. 지원 내역을 보다 새로고침 한 번에 처음부터 다시 로그인해야 했습니다.

해결

로그인 정보를 sessionStorage에 함께 저장하고, AuthContext가 초기화될 때 저장된 값을 읽어 상태를 복원하도록 했습니다.

결과

새로고침이나 직접 URL 진입에도 세션이 유지됩니다. 브라우저를 닫으면 정리되도록 localStorage 대신 sessionStorage를 골랐습니다.

구현 상세

로그인› AuthContext 전역 상태› sessionStorage 저장› 새로고침 시 복원
  • 로그인 상태를 여러 화면이 함께 봐야 해서, 상태 관리 라이브러리를 새로 붙이는 대신 React 기본 기능인 Context API로 해결했습니다.
  • 학교 공용 PC에서도 쓰는 서비스라, 브라우저를 닫으면 자동으로 지워지는 sessionStorage를 택했습니다.

모집글 · 권한

상황

모집글 상세 화면이 로그인 여부만 확인하고 있어, 작성자가 아닌 사용자에게도 수정·삭제 버튼이 그대로 노출됐습니다.

해결

현재 로그인 사용자와 글 작성자를 비교하는 판별을 두고, 그 결과로 수정·삭제와 지원·취소 동작을 분기하도록 정리했습니다.

결과

작성자에게는 관리 동작이, 다른 사용자에게는 지원 동작만 보입니다. 권한 판별을 한곳에 모아 화면이 늘어나도 기준이 흔들리지 않게 했습니다.

구현 상세

모집글 CRUD› 작성자 판별› 관리 · 지원 동작 분기› 지원 · 취소
  • 모집글 CRUD와 지원·취소 흐름을 구현했습니다.
  • 화면이 늘어날수록 타입이 어긋날 위험이 커져, 모집글·사용자 응답 형태를 TypeScript 타입으로 먼저 정의하고 컴포넌트를 붙였습니다.
  • Vercel과 AWS Amplify로 직접 배포해 프론트엔드 배포 환경을 구성했습니다.
